# weekly · 产品需求文档

> 唯一事实来源，与本文冲突时以本文为准；代码与数据库约束见 `AGENTS.md`。
> 部署：阿里云 ECS，`http://weekly.gouxinjie.com`　|　初稿 2026-09-18，最近更新 2026-10-09

---

## 一、产品定位

**产品名：weekly**（与项目代号一致）。一个**以周为单位**的工作记录工具，核心是把「每周写一次总结」这件事做得足够顺手。

- **三个独立模块**：周报（时间轴记录）、待办（清单）、便签（碎片记录），可只用其中一个。
- **多用户**：注册入口长期开放，每个账号的数据完全独立、互不可见。
- **设计原则**：不强制日更（一周一篇，写多写少由用户决定）；模块解耦（模块间只允许显式的单向操作）；时间轴起点固定 2025 且不提供修改入口；数据隔离是硬约束。

## 二、技术形态

| 项 | 方案 |
|---|---|
| 部署环境 | 阿里云 ECS，pm2 守护 |
| 访问域名 | `weekly.gouxinjie.com`，HTTP |
| 反向代理 | Nginx 转发到 Node 内网端口 |
| 数据层 | SQLite，文件位于 `data/weekly.db` |
| 登录方式 | 手机号 + 密码（无短信验证码） |
| 用户模型 | 多用户，注册入口长期开放，按 `user_id` 隔离 |
| 会话有效期 | 30 天 |

**代码组织**：单仓双目录，`server/`（Fastify，所有 SQL 集中在 `src/db/`）与 `web/`（React SPA）各自 `package.json`、各自构建。

| 端 | 选型 |
|---|---|
| 后端 | Node.js 20 LTS + TypeScript、Fastify、SQLite（`better-sqlite3`，WAL 模式）、手写 SQL + 薄封装、argon2、自建 token + `session` 表、dayjs + isoWeek 插件 |
| 前端 | Vite、React 19 + TypeScript、React Router、CSS Modules + SCSS 设计变量、TipTap（编辑，所见即所得，底层仍存 Markdown）、markdown-it（预览，**必须开启 HTML 转义**）、原生 fetch + 薄封装、`useState` + Context |

**实现约定**：SQLite 的 row 类型与 session 对象必须显式建模；所有 SQL 集中在 `server/src/db/`，`user_id` 条件写在明面上；不用 ORM、JWT、状态管理库、UI 组件库。

### ⚠️ 已知并接受的风险：不使用 HTTPS

凭据与内容明文传输，公网扫描会尝试攻击登录 / 注册接口，会话 Cookie 被截获可直接复用。多用户共享，任一处失守影响的是**全部注册用户**。

**补偿措施（不可省略）**：argon2 哈希存密码；登录失败次数限制 + IP 限流；注册限流；Cookie 设 HttpOnly + SameSite；密码强制「数字 + 字母」且 ≥ 6 位；接口不泄露用户是否存在（防手机号枚举）；ECS 安全组只开必要端口、Node 仅监听内网。

**升级路径**：阿里云免费 DV 证书 → Nginx 增加 `listen 443 ssl` → 加 HTTP 跳转 → Cookie 追加 `Secure`。改动量小，建议尽早执行。

## 三、核心概念与关系

| 概念 | 定义 | 创建方 | 可否重命名 |
|---|---|---|---|
| 年节点 | 2025 年 | 系统自动 | 否 |
| 月节点 | 9 月 | 系统自动（按该周的周四归属） | 否 |
| 周节点 | 第 38 周 · 09/14–09/20 | 系统自动（ISO 8601） | 否 |
| 周报 | 某一周的 Markdown 文档，一周一篇 | 用户 | 否（标题即周次） |
| 待办 | 待办条目，独立模块，可选标记所属周次 | 用户 | 是 |
| 便签 | Markdown 碎片记录（带可省标题），独立模块，无完成态、不归属任何周次 | 用户 | 否 |

**关键规则**

1. 年 / 月 / 周三级节点由系统推导，用户不能增删改；周节点即最小内容单元，其下无日节点。月份按该周的**周四**归属（周四是 ISO 周的代表日，也是本周天数最多的月份），因此 2025 年第 1 周（周一为 2024-12-30、周四为 2025-01-02）归入 1 月，不会出现「1 月没有第 1 周」。
2. **三个模块彼此独立**。待办不隶属于周报或任何时间节点，「所属周次」只是可选标签，为 null 时不影响任何行为；便签同样不隶属任何时间节点，也不与待办互转。
3. 模块间只允许一条弱连接：待办标记所属周次后，仅在周报侧作为参考素材显示，待办本身不受影响。**便签不参与任何连接**。
4. 时间轴起点固定为 2025 年，**不提供任何修改入口**（R-11）。
5. **数据隔离**：`user_id` 由服务端从会话推导并强制注入，前端无权指定；写操作按 `id` 更新 / 删除时必须写成 `WHERE id = ? AND user_id = ?`（完整约束见 `AGENTS.md` 红线 1）。

**数据存储约定**

- 一人一周一篇由唯一约束保证：`UNIQUE (user_id, year, week)`。
- 待办的「所属周次」为可空字段。
- 便签一人多张、**不设唯一约束**；无完成状态、无周次字段，也没有排序字段——列表固定按「置顶优先、新的在前」排列。
- 周次计算按 ISO 8601（周一为一周起点），用 dayjs 的 isoWeek 插件推导，不手写日历逻辑；同一周不跨年拆分，按 ISO 年归属。
- 起点是服务端常量（`START_YEAR = 2025`），服务端校验并拒绝任何早于 2025 年第 1 周的写入；跨年时自动把新年份加入树。
- 备份即复制 `data/weekly.db`；服务端定时 `VACUUM INTO` 生成一致性快照，配合 ECS 磁盘快照。

### 4.1 周报模块

| R-01 | 三层树导航 | 年 > 月 > 周，年与月均可折叠展开，折叠状态持久化；**未写的周同样出现在树中** | P0 |
| R-02 | 定位到本周 | 打开应用自动展开当年，选中本周 | P0 |
| R-03 | 上一周 / 下一周 | 编辑区顶部快捷切换 | P0 |
| R-04 | Markdown 编辑 | 编辑 / 预览双模式切换 | P0 |
| R-05 | 自动保存 | 输入停止 800ms 后落库，显示「已保存 / 保存中」 | P0 |
| R-06 | 写作状态角标 | 周节点显示「已写 / 未写」，未写的周为灰色 | P0 |
| R-07 | 全部展开 / 收起 | 一键操作当前年份下所有周 | P0 |
| R-08 | 周报模板 | 模板**不自动注入**，由用户从右栏「应用模板」按需注入，可一键清空 | P1 |
| R-09 | 单周导出 | 导出 Markdown / 复制到剪贴板 | P1 |
| R-10 | 补写历史周 | 可跳到 2025 年第 1 周及其后任意周 | P1 |
| R-11 | 时间轴起点 | 固定从 2025 年开始，之前的年份不出现在树中 | P0 |
| R-12 | 字数统计 | 编辑区显示本周字数 | P2 |
| R-13 | 连续记录统计 | 显示已连续记录多少周 | P2 |
| R-14 | 年份归档 | 一整年写完后可标记归档，默认折叠 | P2 |
| R-15 | 批量导出 | 把本年度 / 最近 3 或 6 个月 / 自定义周区间内的周报合并为**单个** Markdown 文件 | P1 |

**R-08 模板内容**（点「应用模板」时注入，会覆盖当前内容并二次确认）：

```markdown
### 本周进展

### 遇到的问题

### 下周计划
```

**模板不自动注入**：未写过的周打开后编辑区保持空白，只有真正敲入内容才会落库并标记「已写」——否则「点开看一眼」就会被自动保存把模板写进库里。判定口径统一为 **`content` 去空白后为空即不算已写**（服务端 `listWrittenWeeks` 与前端角标同源）。

**R-15 批量导出口径**（入口常驻周报页顶栏，编辑态与展示态都可直达；移动端退化为同尺寸图标）：

- 产物是单个 `.md`：每周一节（二级标题写「ISO 年 + 周次（起止日期）」），节间 `---` 分隔，文档头部为一级标题与导出时间。
- **只导出写过的周**，与 R-06 的「已写」判定同源。
- **范围按「周」而非日期**：起止顺序与跨度用 `(年, 周)` 推出的周一日期计算，不用合序号相减（后者跨年会虚增跨度）。
- 「最近几个月」按周的归属月份统计（周四定月，与左栏树的月份分组同一口径）。
- 单次上限 200 周，超出返回 400 并提示缩小范围；区间内一篇都没有时不下载空文件，改为就地提示。

### 4.2 待办模块

**定位**：独立待办清单，不隶属于周报或任何时间节点，可以只用待办、完全不用周报。
**内容形态**：纯条目（一行文本 + 勾选框），不承载长文本。**组织方式**：单一清单 + 状态分组，不建文件夹、不做嵌套。

| 编号 | 需求 | 说明 | 优先级 |
|---|---|---|---|
| M-01 | 待办条目 | 一行文本 + 勾选框，回车即新建，支持编辑删除 | P0 |
| M-02 | 状态分组 | 置顶、未完成两段留在主干的周分组内；已完成段下沉到清单末尾单处折叠（默认折叠但永久保留，展开后内部仍按周倒序分段） | P0 |
| M-03 | 标记所属周 | 标记 `year + week`；**新建时默认写入当前 ISO 周**，之后可改可清除；为 null 时不影响任何行为 | P0 |
| M-04 | 置顶 | 重要条目置顶到最上方 | P0 |
| M-05 | 拖拽排序 | 同组内可拖拽调整顺序 | P1 |
| M-06 | 清单筛选 | 四选一：全部 / 本周 / 未完成 / 已完成，各项带计数。**「本周」按「所属周」判定**（手动标记优先，未标记按创建时间推导），与分组同一口径 | P1 |
| M-07 | 过期提示 | 标记周次已过且未完成 → 挂「过期」小标签（危险色）；不改分组、**不染整行底色**，仅视觉提示 | P2 |
| M-08 | 从周报转待办 | 周报中选中一行转为待办 | P2 |
| M-09 | 计数角标 | 「待办」标签显示未完成条数 | P2 |

### 4.3 便签模块

**定位**：负责「还没成型的碎片」——随手记一句话、一个电话号码、一条临时信息。与待办的边界是**没有「完成」语义**：便签永远只是一段 Markdown 文本，不出现勾选框，也不标记周次。

**内容形态**：可省的单行标题（上限 100 字）+ Markdown 正文（**不限字数**，长内容在卡内滚动、全文走预览弹窗）。卡内编辑的是 **Markdown 原文**，渲染成品通过「预览」按钮在弹窗里看；预览按「一行一条」的记法，**单个换行也换行**，不要求段落之间空一行。**不支持图片与富文本编辑器**——图片需要文件存储与上传能力，本项目不具备；富文本编辑器则与「随手记」的轻量定位不符。

**组织方式**：不分组、不建文件夹、不做标签；固定按「置顶优先、新的在前」，靠顶部搜索定位。

**容量上限**：单用户最多 2000 张，正文总占用不超过 20 MB。单张正文不限字数，但多用户共用一个库文件，总量必须有闸门；两类上限触顶时写入被服务端拒绝，清理几张即可继续。

| 编号 | 需求 | 说明 | 优先级 |
|---|---|---|---|
| N-01 | 便签卡片 | 一张便签一张卡片，**卡内直接编辑 Markdown 原文**（点击即可写，不需要「进入编辑」）；顶部为可省的单行标题，正文随输入自撑高度，超出上限转为卡内滚动 | P0 |
| N-02 | 新建便签 | 「＋ 新建」弹出弹窗，填好标题与正文后创建；两项都不填直接点「创建」即得到一张空白便签并自动聚焦。**允许空白存在**，标题与正文都为空时失焦即丢弃，不在墙上留下空白卡片 | P0 |
| N-03 | 自动保存 | 输入停止 800ms 后落库；**每张便签各有一套**「保存中 / 已保存」；离开页面时补发尚未落库的改动 | P0 |
| N-04 | 便签纸颜色 | 三种：默认 / 黄 / 绿，取色即存；服务端按白名单校验 | P0 |
| N-05 | 置顶 | 置顶的便签固定在列表最前 | P0 |
| N-06 | 删除便签 | 二次确认后删除（内容型数据，误删无法恢复） | P0 |
| N-07 | 便签墙 | 等宽多列网格：按行从左到右排列，列数随窗口宽度自适应；卡片各自成高、顶部对齐，**一张长便签不把整行拉高** | P0 |
| N-08 | 搜索便签 | 顶部搜索框，在已加载的便签里按**标题与正文**过滤（前端本地过滤，不额外请求） | P1 |
| N-09 | 便签标题 | 单行标题（上限 100 字），可省；用于在一墙碎片里认人，不参与排序 | P0 |
| N-10 | 预览便签 | 卡上的「预览」按钮把 Markdown 原文渲染成成品，在弹窗里看全文；空白便签按钮禁用 | P0 |

**不做**：便签转待办、插入周报、拖拽排序、标签、归档、图片与富文本编辑器。便签只进不出。

| G-01 | 注册 | 手机号 + 密码，入口长期开放；手机号唯一。密码要求：**数字 + 字母组合，长度 ≥ 6 位** | P0 |

| G-14 | 概览首页 | 展示本年已写周数、待办未完成数（不在 MVP） | P2 |

| G-16 | 移动端骨架 | 视口 ≤ 1023px 切换为移动端骨架：页签栏落到底部，左列与右栏改为覆盖式抽屉；≥ 1024px 的桌面端骨架完全不变 | P2 |

**G-05 处理流程**：用户联系 → 核对身份 → 操作数据库重置密码哈希 → 通知用户。不做邮箱 / 密保找回，代价是依赖人工响应。

**错误反馈约定**：表单校验与保存失败一律**就地显示**（周报页长时间停留，Toast 容易被忽略）；仅跨区域的短反馈（导出成功、已登出所有设备、便签创建成功）用顶部 Toast。

**数据隔离验证**：`db/` 层必须有跨用户访问测试——用 A 的会话调接口改 / 删 B 的记录 id 必须失败。用 Node 内置 `node --test`，不引入测试框架。这是本系统最严重的单点风险，不可省略。

**未来规划（移出 MVP）**：全局搜索（SQLite 启用 FTS5 即可）、整库数据导出 / 导入（复制 `.db` 即可）、启用 HTTPS、自助密码找回（需邮箱或短信服务）、用户管理后台、回收站、概览首页、更多主题（新增只需加变量块 + 选项）、多标签页实时同步（需 WebSocket）、移动端手势（左右滑动切周、下拉刷新、长按拖拽排序）。

## 五、界面结构

### 5.1 未登录态

访问站点首先看到登录页，登录 / 注册同页切换，注册入口**不设关闭条件**，注册页底部同样显示联系方式。登录失败提示统一为「手机号或密码错误」，不区分账号是否存在。

### 5.2 三种骨架

登录后界面共有**三种骨架**，切换标签页即整体换骨架。登录页**不属于骨架体系**——它是独立的全屏居中卡片，无左栏无右栏。

```
【周报态 · 展示：右栏是浮层，不占中栏宽度】
┌────────┬────────┬──────────────────┐
│ 页签栏  │ 时间轴  │       中栏        │
│ 200px  │ 220px  │      自适应       │
│  页签   │ 三层树  │      周报正文      │
└────────┴────────┴──────────────────┘
           右缘一枚竖排按钮「查看本周待办」（本周有待办时高亮）
           点开 → 自右滑出 220px 浮层「本周待办」，可收起

【周报态 · 编辑：右栏是常驻一列】
┌────────┬────────┬──────────────────┬──────────┐
│ 页签栏  │ 时间轴  │       中栏        │   右栏    │
│ 200px  │ 220px  │      自适应       │  220px   │
│  页签   │ 三层树  │      编辑区       │ 模板/插入 │
└────────┴────────┴──────────────────┴──────────┘

【待办态】
┌────────┬────────┬──────────────────┐
│ 页签栏  │ 筛选列  │       中栏        │
│ 200px  │ 220px  │      自适应       │
│  页签   │ 四项筛选 │       清单        │
└────────┴────────┴──────────────────┘

【便签态】
┌────────┬──────────────────────────────────┐
│ 页签栏  │               中栏                │

│  页签   │  标题 + 搜索 + 新建 + 便签墙（多列）│

```

| 区域 | 周报态 | 待办态 | 便签态 |
|---|---|---|---|
| 页签栏 | 200px：logo + 页签 + 底部账号区 | 同左（宽度一致，位置不跳动） | 同左 |
| 左列 | 220px：`时间轴` 标题 + 年 / 月 / 周三层树 | 220px：`筛选` 标题 + 全部 / 本周 / 未完成 / 已完成（行尾计数） | **整列移除** |
| 中栏 | 标题栏 + 编辑区 + 工具条（最小 480px） | 标题 + 搜索 + 新建输入框 + 分组清单 | 标题 + 搜索 + 新建 + 多列便签墙 |
| 右栏 | 展示态是**浮层**（220px，盖在中栏之上、不占宽度，收起时只在右缘留一枚竖排入口按钮）；编辑态是常驻 220px 列（模板 / 插入 / 导出） | **整栏移除**，不是收起 | **整栏移除** |

**移动端骨架（视口 ≤ 1023px）**：同一套 DOM 换排布，不复用桌面端的三列宽度。

```
┌────────────────────────────────────┐
│  顶栏：抽屉入口 + 年份切换 + 操作    │
├────────────────────────────────────┤
│        中栏（全宽，唯一内容列）       │
├──────┬──────┬──────┬──────┬────────┤
│ 周报 │ 待办 │ 便签 │ 设置 │  头像  │
└──────┴──────┴──────┴──────┴────────┘
        底部页签栏 + 安全区
```

- **底部页签栏**取代左侧 200px 页签栏：四个页签等宽横排，品牌区收起，账号区只剩一枚头像（账号名与手机号在设置页看）。
- **左列与右栏**变为覆盖式抽屉：左列自左滑入、右栏自右滑入，点遮罩收起，两者同时只开一个。入口按钮跟着页面走——周报态由骨架摆在顶栏最前面（「时间轴」与「待办 / 插入」），待办态由页面放进自己的标题行（「筛选」，在搜索框左侧）。
- **中栏**取消 480px 最小宽度并停止横向滚动，是移动端唯一的内容列；高度用 `100dvh` 而不是 `100vh`（地址栏伸缩时底部页签栏不会被推出屏幕）。
- 便签态没有左列与右栏，因此不渲染抽屉入口；设置态同理。

**关键规则**

1. 页签栏宽度三态一致（200px），切换时页签与账号区不跳动，只有右侧内容换。
2. 左列在周报态与待办态都在且同宽（220px），只是内容不同：周报态是时间轴三层树，待办态是筛选列表。
3. 左列与中栏共享顶栏——周报态的年份切换落在左列正上方，与 `时间轴` 标题左对齐。
4. 周报**展示态**与待办态都没有常驻右栏（展示态的右栏是浮层，展开与收起都不占宽度），中栏宽度只受页签栏与左列挤压。
5. **便签态没有左列也没有右栏**，只有页签栏 + 中栏，是三种骨架里中栏最宽的；便签不设筛选，只保留顶部搜索。
6. 窗口变窄时，周报**编辑态**的常驻右栏先被压缩，其次才出现横向滚动；展示态的右栏是浮层，不参与压缩。
7. 页签在页签栏顶部，**整个应用没有顶部导航栏**。
8. 设置页也不属于三种骨架——它是单列居中布局，从页签栏的「设置」页签进入。

### 5.3 页签与左栏

| 标签页 | 左栏内容 |
|---|---|
| 周报 | 三层树（年 > 月 > 周），只读结构；**2025 年起所有周全部列出**，有内容的周带绿色角标（`--color-saved`），未写的灰色；默认只展开选中周所在的月份，月标题在该月有内容时行尾显示「已写 / 全月」周数（如 `3/5`） |
| 待办 | 筛选器：全部 / 本周 / 未完成 / 已完成，各项行尾带计数；不做树 |
| 便签 | **不设左列**，只有页签栏 + 中栏 |

三个标签互不依赖，可以只用其中一个。多用户不影响界面结构——数据来源在服务端限定，前端无感知。

### 5.4 中栏三种视图

| 视图 | 触发 | 结构 |
|---|---|---|
| 周报编辑 | 选中周节点 | 标题栏（周次 + 日期 + 保存态 + 字数）→ 编辑 / 预览区 → 工具条 |
| 待办清单 | 切到待办标签 | 顶部固定新建输入框 → 按所属周分组（新周在前）的清单 |
| 便签墙 | 切到便签标签 | 标题行（`便签` + 搜索 + ＋ 新建）→ 等宽多列网格的便签卡片 |

中栏无空白屏：周报态未写时编辑区保持空白、可直接书写；待办态输入框始终在、光标可直接落入；便签态点「＋ 新建」在弹窗里创建，两项都留空即得到一张空白便签并聚焦。

### 5.5 右侧抽屉

右栏在周报的两种模式下形态不同：

- **展示态：浮层**。默认收起，右边缘只留一枚竖排入口按钮「查看本周待办」——本周有标记的待办时高亮为主色实底，否则是素净的描边按钮。点开后自右滑出 220px 浮层盖在中栏之上，**展开与收起都不占中栏宽度**；浮层里是标记在本周的待办条目，**只读展示，不可在此勾选或编辑**，点浮层左缘的圆形把手收起。
- **编辑态：常驻列**。宽 220px，可收起（收起后中栏全宽），放模板 / 插入 / 导出面板，编辑时随手可用。

切换模式时右栏按上面的规则自动落位（进编辑态展开、回展示态收起）；模式不变时手动收起后不会被再顶开。待办态与便签态下整栏不存在。

### 5.6 各区域元素清单

**左栏 · 周报态**

| 元素 | 行为 |
|---|---|
| 年 / 月节点 | 均可折叠，默认展开选中的年份；月节点缩进一级，该月有已写周时补绿色圆点，一周未写时整行淡显 |
| 周节点 | 时间轴圆点 + 「第 38 周 · 09/14–09/20」；选中态为浅底圆角卡片，圆点放大成同心圆环（已写绿环、未写主色环） |
| 展开全部 / 收起全部 | 作用于当前年份下所有周 |
| 定位本周 / 跳转到周次 | 定位本周（已在本周时置灰）；跳转支持输入「2025 年第 15 周」直接定位（G-17） |
| 底部账号区 | 头像 + 账号名 + 手机号脱敏（`138****1111`）；仅展示，登出统一在设置页 |

**左栏 · 待办态**：筛选器四项（选中项为浅底圆角卡片 + 主色加粗文字，行尾右对齐计数）；底部账号区与周报态一致，位置不跳动。

**中栏 · 周报态**

| 元素 | 行为 |
|---|---|
| 标题栏 / 保存态 / 字数 | 「第 38 周 · 2026/09/14 – 09/20」+ 保存态徽标 + 本周字数 |
| 上一周 / 下一周 | 快捷切换（R-03） |
| 编辑 / 预览 | 双模式切换，保留滚动位置 |
| 编辑区 | 所见即所得编辑（TipTap），底层为 Markdown |
| 工具条 | 撤销 / 重做 / 段落格式（正文 / H1-H6）/ 字号 / 加粗 / 斜体 / 删除线 / 无序·有序·待办列表 / 引用 / 代码块 / 分割线 / 表格 / 链接 / 文字颜色 / 背景颜色；所有格式都能无损往返到 Markdown（字号与颜色以白名单内的内联 span 保存），不做对齐 |

**右栏 · 周报态（展示态为浮层，编辑态为常驻列）**

| 元素 | 行为 |
|---|---|
| 入口按钮 | 仅展示态：竖排「查看本周待办」贴在中栏右缘；本周有待办时高亮为主色实底，无待办（或加载中 / 失败）时为描边按钮；点击滑出浮层，点浮层左缘的圆形把手收起 |
| 标题 / ＋ 新建 | 「本周待办」；「＋ 新建」跳待办页并带上当前查看的周（`/todo?year=&week=`） |
| 待办条目 | 只读，不可编辑（保持模块单向） |
| 空态 | 「本周暂无标记的待办」，附「去待办添加」，同样带上当前查看的周 |

**中栏 · 待办态**

| 元素 | 行为 |
|---|---|
| 新建输入框 | 常驻顶部，Enter 新建并保持焦点；行内标出默认归属周——取当前 ISO 周，从周报页带 `?year=&week=` 跳来时取该周；要改标记在创建后走「⋯」菜单 |
| 分组标题 | 按**所属周**分组并倒序（手动标记优先，未标记按创建时间推导）：当周显示「本周 · 第 39 周（N）」，其余显示「第 38 周 · 26（N）」；组内置顶优先、创建先后。**主干只渲染未完成，一条未完成都没有的周整组不渲染**；N 是该周未完成条数——已完成另在末尾汇总，混进 N 会与「这周还剩什么事」的阅读预期对不上 |
| 已完成汇总区 | 位于清单末尾、主干之下，用分隔线隔开；全清单**只有这一个折叠控件**，标题「已完成（N）」默认折叠、可点开，展开后内部仍按所属周倒序分段，段内可拖拽排序 |
| 已完成平铺 | 筛选为「已完成」或搜索关键词非空时不再分层，已完成就地留在所属周分组内平铺——这两种场景都必须摊开：前者收进折叠区等于整屏看不到内容，后者会让命中的未完成条目凭空消失 |
| 条目 | 勾选框 + 文本 + 可选小标签：置顶 / 分类 / 未标记 / 过期。周次已由分组标题表达，行上不重复；未标记（浅色）表示不进周报「本周待办」，过期（危险色）表示标记的周已过且未完成；两种状态都不染整行底色 |
| 勾选反馈 | 勾选 / 取消时弹一条顶部轻提示（1.8s）交代去向：条目会移到末尾「已完成」区；若当前筛选把它挡在外面（如「未完成」筛选）则改为「已移出该筛选」；写入失败回滚时提示「未保存，已还原」 |
| 空态 | 「还没有待办，在上面输入一条试试」 |

**中栏 · 便签态**

| 元素 | 行为 |
|---|---|
| 标题行 | 「便签」+ 搜索框 + 「＋ 新建」；搜索在已加载的便签里按标题与正文本地过滤 |
| 新建弹窗 | 标题（单行、上限 100 字）+ 正文（多行 Markdown 原文），两项都可留空；底部「取消 / 创建」，Esc、点遮罩、取消均可关闭，Ctrl / ⌘ + Enter 直接创建。创建失败就地提示且**弹窗不关**、已填内容不丢；创建成功即关闭并 Toast 回执「已创建便签」，两个字段都为空时新便签自动聚焦，已写好内容的不抢焦点 |
| 便签卡片 | 整卡底色即便签纸色；顶部标题输入（单行、可省，比正文大一档、加粗），下方内容区**直接可编辑 Markdown 原文**，随输入自撑高度，超出上限转为卡内滚动 |
| 卡片底部 | 更新时间（`2026/09/23`）+ 该张便签自己的保存态（保存中 / 已保存） |
| 纸色 / 置顶 / 删除 | 三种纸色圆角色块（当前色内置对勾 + 主色描边）；置顶后固定最前、图标转主色；删除需二次确认 |
| 预览 | 卡内右侧常显（内容为空时禁用），把原文渲染成成品在弹窗里看全文；弹窗内正文滚动，Esc / 点遮罩 / 右上角 ✕ 关闭 |
| 便签墙 | 等宽多列网格，按行从左到右排列，列数随宽度自适应；卡片各自成高、顶部对齐。正文可视高度上限约 4 行（96–100px，不论长短卡片高度基本一致），超出在卡内滚动 |
| 空态 | 「还没有便签，点「＋ 新建」随手记一笔」，附「新建便签」文字链 |

## 六、已拍板决策记录

无遗留待定问题，以下决策均已落进正文。

| 编号 | 问题 | 决策 |
|---|---|---|
| Q1 | 周次计算标准 | **严格 ISO 8601**（周一为一周起点） |
| Q2 | 跨年周如何归档 | **按 ISO 年归属**，一周不拆分 |
| Q3 | 数据规模 | 预期注册用户 10 人以内、数据跨度 3 年内（约 160 周）；**不做虚拟滚动**，树超过 300 节点再优化 |
| Q4 | 已完成待办保留策略 | **永久保留**——「做完了什么」正是写周报的素材 |
| Q5 | 待办截止日提醒 | **仅标记周次**，过期未完成则周次标签转危险色；不做提醒推送 |
| Q6 | 首次打开是否预置示例 | **完全空态 + 引导**——预置假数据会让用户先做「删除」这件负功 |
| Q7 | 多标签页 | **仅检测提示**，不做实时同步 |
| Q8 | 概览首页 | **不做**，登录后直接落在本周周报 |
| Q9 | ECS 规格与备份 | 最小规格；**手动快照 + cron 定时 `VACUUM INTO`**，不引入自动快照服务 |
| Q10 | 多端同时在线 | **允许多设备**（手机 + 电脑是真实场景）；「登出所有设备」可一次清空 |
| Q11 | 用户管理后台 | **直接改数据库**，不做后台页 |
| Q12 | 数据隔离验证 | **写跨用户访问测试**，仅覆盖 `db/` 层的归属校验，用 `node --test` |
| Q13 | 右栏是否可拖动调宽 | **固定 220px**（浮层与常驻列同宽），不吃拖拽与持久化的复杂度 |
| Q14 | API 文档 | **接口注释即文档**，不生成 OpenAPI——自用工具读代码更快 |
| Q15 | 错误反馈形式 | **就地显示**用于表单校验与保存失败；**顶部 Toast** 仅用于跨区域的短反馈（导出成功、便签创建成功等，弹窗一关操作与结果就不在同一处了） |
| Q16 | 主题 | **三套主题（浅色 / 暖纸 / 深色）**，存本机 localStorage，不随账号同步 |
| Q17 | 移动端策略 | **同一套 DOM 换骨架，不做独立移动端页面**。断点 1023px；≤ 1023px 时底部页签栏 + 左列 / 右栏覆盖式抽屉，中栏取消 480px 最小宽度。触屏上 HTML5 拖拽不生效，待办排序改走「⋯」菜单的上移 / 下移 |
| Q18 | 周报编辑形态 | **所见即所得（TipTap）**，底层仍存 Markdown；预览用 markdown-it。CodeMirror 源码编辑方案作废 |
| Q19 | 便签的入口形态 | **新增第四个页签**（`/notes`），不做悬浮便签板 |
| Q20 | 便签的内容形态 | **Markdown 原文 + 可省标题**（正文不限字数、标题上限 100 字）；不做图片——那需要文件上传与存储 |
| Q21 | 便签与其它模块的关系 | **不做任何桥接**：不转待办、不进周报，便签只进不出 |
